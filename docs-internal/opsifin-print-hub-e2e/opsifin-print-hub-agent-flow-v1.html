Lima sistem, satu jejak invoice

Klik komponen untuk melihat tanggung jawab, data yang dipegang, dan hal yang tidak boleh dilakukannya. Garis solid adalah data utama; garis putus-putus adalah status atau callback.

opsifin-main menentukan apa

  • Invoice yang siap dicetak.
  • Isi dan Link PDF.
  • Status bisnis setelah callback.

Hub menentukan ke mana

  • Tenant, source, binding, dan printer.
  • Job state, lease, retry, callback.
  • Audit dan bukti snapshot.

Agent mengerjakan fisik

  • Melihat printer Windows.
  • Merender PDF ke GDI.
  • Memantau JobId dan mengirim event.
Integration ID
UUID publik yang mencocokkan tenant Hub dengan satu opsifin-main.
Binding
Route dari identitas printer legacy ke destination printer Hub.
Snapshot
PDF kanonis + SHA-256 yang benar-benar dikirim ke Agent.
Lease
Hak sementara Agent atas satu job; default 120 detik.
Print run
Satu siklus cetak. Manual retry menaikkan nomor run tanpa menghapus histori.

    Simulator: apa yang terjadi jika…

    Pilih skenario. Simulator tidak menyentuh Hub, Agent, printer, atau database; ia hanya memvisualisasikan aturan state machine yang berjalan dan gap yang ditemukan audit.

    Retry printing

    • Memakai snapshot lama.
    • Untuk Agent/spooler/printer sebelum hasil ambigu.
    • Membuat print run baru.

    Refetch and retry

    • Mengambil PDF baru dari source.
    • Dikerjakan Horizon.
    • Snapshot lama tetap menjadi bukti.

    Confirm physically printed

    • Direkomendasikan untuk hasil ambigu.
    • Tidak mencetak ulang.
    • Butuh reason, actor, dan audit.

    Lease expired setelah spooled

    Kode Hub masih mengembalikan state printing ke queued seperti claimed.

    Rekomendasi: PRINT_RESULT_UNKNOWN, tidak auto-retry.
    Hasil fisik ambigu

    UI sekarang hanya Retry printing dan Refetch and retry.

    Rekomendasi: Confirm physically printed dengan reason + audit.
    Host Link PDF

    HTTP(S) valid masih dapat menunjuk host apa pun.

    Rekomendasi: Base URL host + allowlist per connection.
    Retensi snapshot

    Schema punya expires_at, tetapi belum ada expiry/purge aktif.

    Rekomendasi: 90 hari per tenant + legal hold.
